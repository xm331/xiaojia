# 开发日志 · 踩坑实录

> 这个项目迭代过二十多个版本，下面每一坑都是真实发生过、真排查过的。
> 每条按「现象 → 排查 → 根因 → 修复 → 教训」记录——面试聊到的每一个细节都能在这里对上号。

---

## 1. 流式回调漏传：首字延迟反而变长

**现象**：接入分段流式渲染后，回复不是逐句蹦，而是卡两秒整段砸出来。

**排查**：顺着渲染链路逐层打点，发现底层函数确实在逐块回调，但 UI 层一次都没收到。

**根因**：中途加了一层封装 `callModelNoRepeat(...)`，调用底层时把第 5 个参数 `onChunk` 漏了。签名变更时只改了一处，包装层没跟着改。

**修复**：补传。修完实测：渲染块数从 0 → 25。

**教训**：函数签名变更必须 grep 全部调用点；中间层的参数透传最容易漏。

---

## 2. 45 秒一刀切超时：五句里两句「不想说话」

**现象**：用户频繁看到 AI「……不想说话」，但抓包显示模型明明还在正常吐字。

**排查**：复盘超时逻辑——定时器从**请求发出**那一刻起算，全程不重置。模型思考 20s + 输出 30s，还没说完就被掐。

**根因**：把「没响应」和「还在干活」当成了同一件事。

**修复**：拆成三层——①等响应头 60s（并发时服务端排队很正常）②流式空闲 30s，**每收到一块数据就重置**③硬上限 180s 防彻底挂死。误杀归零。

**教训**：超时策略必须区分「卡死」和「慢」：只看总时长会把慢但健康的长回复误杀。

---

## 3. 接龙抢跑：后面两句先出，要接的那句还没影

**现象**：队形接龙（「你只是怕了」→「这谁不怕」）播出顺序乱了——起头那句「根本就没有这样的X」还没出现，后面两句已经蹦出来了。

**排查**：这个功能经历过三次反转。v1 加了串行门闩（起头说完别人才开口）→ 换来「三人轮流发言，太慢」；v2 拆掉门闩改成三人并发抢播 → 换来这个 bug。

**根因**：队形台词是**前端写死的字符串**，毫秒级入队；起头那句要等模型，一两秒。两种节奏混在同一个并发流程里，抢跑是必然的。

**修复**：按「这一轮有没有队形」分成**两条物理隔离的通道**——有队形走严格串行（每句 `await` 到真正播完），没队形保持并发抢播。一行 `const formation = ...` 分岔。

**关键细节**：串行判断只认「**屏幕上真正播出去的**」（在渲染函数里写入的 `played` 记录），而不是「谁生成了什么」。否则模型会去接一句还躺在队列里、根本没出声的话。

**教训**：并发和顺序是互斥需求，不能为了复用代码硬塞进一条路径。这句注释现在就写在代码里。

## 4. 随机补梗：用户说「好悠哉啊」，AI 回「你明明看见梅姨了快跑」

**现象**：梗和用户的话八竿子打不着，甚至编出对话里不存在的人物。

**排查**：梗挑选逻辑是「命中优先 + **不足随机补满**」。用户这句话在 67 条梗里零命中，塞给模型的 6 条候选全是随机的——梅姨就在里面。再叠上「看见派」人设模板（「你明明看见他XX了」），模型就硬接出了幻觉剧情。

**修复**：两层——①不沾边就**一条都不给**，宁可不玩梗也不塞不相关的东西；②每条梗人工标注 2~5 个口语关键词（同义词、别称、场景词），命中才算贴题，上限 3 条。

**验证**：17 项测试。「好悠哉啊」→ 0 条；「你别装逼了」→ 正确捞出对应的梗；「你放**我**鸽子啊」这种带插入语的句子也修过一次关键词匹配。

**教训**：给模型的候选越少越准。这个功能的目标是「不乱来」，不是「每次都出」。

## 5. 钥匙失效提醒只弹一次，之后永久静音

**现象**：第二次钥匙失效后，界面只剩「……没接上话」，用户完全不知道是钥匙的问题。

**根因**：防重复用的是一个 bool（`keyDeadShown`），弹过一次置 true，全文件没有任何重置路径。

**修复**：改成 5 分钟时间窗 + 换钥匙成功立刻清零。同一轮三个人一起报错也只弹一次。

**教训**：「防重复」的正确形态是时间窗或每轮重置，不是永久 flag——它把「不要烦用户」做成了「再也不告诉用户」。

## 6. Service Worker 里的 `const` 重赋值

**现象**：SW 注册失败，离线缓存和版本更新全废。

**根因**：`fetch` 拦截器里请求对象要补参数重赋值，声明却用了 `const`。`node --check` 之前没跑过这段（它不在主 script 块里）。

**修复**：`const` → `let`；缓存版本号 bump；注册路径加 `updateViaCache:"none"` 防浏览器用 HTTP 缓存把旧 SW 又发回来。

**教训**：PWA 的更新链路是「新 SW → 新缓存 → 删旧缓存」，任何一环用错缓存策略都会让用户永远停在旧版本。

---

## 7. 加了 preconnect，首字却没变快

**现象**：加了 `<link rel="preconnect">`，冷启动延迟没改善。

**根因**：跨域预连接**必须带 `crossorigin`**——不带的话浏览器建立的是无凭据连接，和后续 CORS fetch 对不上，握手白做，连接复用不了。

**修复**：补上属性；再加第二个时机——**用户开始打字时**动态触发。因为浏览器空闲十几秒就会回收预连接，静态标签握完的连接到用户真正发消息时早就断了；「一动手就握」等发送时正好是热的。

**教训**：性能优化要验「连接有没有被实际复用」，不是「加了没有」。移动网络 TLS 握手 100~300ms，值得做，但要做对。

## 8. 对外部 AI 的审查意见：6 条核实下来，2 真 3 否 1 存疑

**背景**：把源码交给另一个 AI 做代码审查，拿回 6 条意见。

**逐条核实的结果**：
- ✅ 钥匙弹窗永久静音——真 bug，修复（见第 5 条）
- ✅ 「云同步」只有格子号没有网络实现——属实，但结论不是「接后端」，而是先把注释改诚实，别让下一个读代码的人误会
- ⚠️ 模型是否支持视觉输入——存疑，需要实测才能动，没有贸然改
- ❌ 「闲聊时砍掉共享记忆能省 400 字」——**账算错了**：省 1200 token/轮 ≈ 0.001 元，代价是三人变回陌生人
- ❌ 「gist 共享一份能省两份文本」——省的是存储不是 token：三个请求各自都要带这段上下文，3×140 字改完还是 3×140。真正的收益是三人记忆对齐，按这个理由才值得做
- ❌ `splitLong` 正则回溯——有长度门槛挡着，实际碰不到，不动

**教训**：审查意见是**假设**，不是结论。每一条都要对照代码验证、把账算出来。这轮真正修掉的是 2 条，省下的反而是不乱改。
